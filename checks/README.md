# Exact Checks

These scripts check the finite examples, counterexamples, and identities of the paper "Risk Assessment for Changes to AI Agents" and compute the laws of their finite mechanisms with exact rational arithmetic (`fractions.Fraction`); seeded random generation of test cases and rounding for display use floating point. `verify_budget_limits.py` also computes logarithms, binomial probabilities, a dynamic program, and a numerical enumeration of the log (omitted mass below 1e-11) in floating point, as its docstring says. They use only the Python standard library, except that `verify_budget_sufficiency.py` and `verify_budget_strata.py` also use numpy. Each script builds its finite mechanisms explicitly, as ordered lists of named kernels with declared inputs, and computes every reported number from the enumerated laws. No agent data are used.

Run each script from the repository root:

```
python checks/verify_foundation.py
python checks/verify_diagnostic.py
python checks/verify_replay.py
python checks/verify_horizon.py
python checks/verify_supported.py
python checks/verify_unsupported.py
python checks/verify_coupling.py
python checks/verify_eval_awareness.py
python checks/verify_composition_replacement.py
python checks/verify_budget.py
python checks/verify_budget_limits.py
python checks/verify_restoration.py
python checks/verify_budget_sufficiency.py
python checks/verify_budget_strata.py
python checks/verify_snapshot_design.py
```

Alternatively, run all checks in sequence: `python checks/run_all.py`.

All finish in seconds except `verify_budget_sufficiency.py` (about one minute), `verify_unsupported.py` (about two minutes), and `verify_budget_strata.py` (about two minutes, with seeded Monte Carlo checks). Each script prints its checked results, as PASS lines in all scripts but `verify_foundation.py`, and raises an assertion error on any mismatch. `verify_unsupported.py` loads `verify_supported.py` from the same folder, and `verify_restoration.py` loads `verify_replay.py` and `verify_budget.py`.

Appendix H of the paper points to this file, and `supplement/appendix-H.md` maps each script to the claims it checks. The table below adds the decisive witness of each script. The section after it records the worked examples that the appendix now cites only by check name, so the code release carries them.

## Worked Examples Kept Here

The examples below are not in the paper; the checks that compute them document them here.

### Replay and Logging (`verify_replay.py`)

- **Shared input breaks saturation (T1-14).** A task has type c or p with probability 1/2 each, the replacement retries both, and an unknown kernel N in {0,1} after a retry reads only the action. With L = N for type c and L = 1 - N for type p, each continuing prefix alone allows any law on {0,1}, yet every mechanism gives the replacement law Bern(1/2), so the order bounds are not attained. When N also reads the type, the inputs are distinct and the bounds are attained. The paper keeps this as one sentence after condition (S).
- **Declared later-abort valuation (T1-16).** After a retry, a later replaced gate skips the costly branch, so the feasible set is {0,1}; a declared valuation of the later abort leaves only means in [4/5, 1], so the bounds are outer.
- **Tail sensitivity (T1-7).** With replayed mass 9/10 at loss 0 and continuing mass 1/10 on a loss in {0,1}, the mean lies in an interval of width 1/10, while CVaR at level 0.9 can take any value in [0, 1].
- **Restricted law classes (T1-17).** A context bit X has an unknown law, a logged fair tape U is independent of X, the replacement aborts when U = 1 with valuation delta_0, and the loss under execution is X. A log of (X, L) that omits U fails the fibre condition at {X = 1, L = 1}, yet in the class where U is fair and independent of X the replay summary is a function of the log law. The paper keeps this as the witness in the scope paragraph of Proposition 3.1 (`thm:logging`).
- **Strict logging (T1-5).** An outcome-only log that omits the gate input places an agreement path with contribution delta_1 and a terminal path with contribution delta_0 in one fibre; laws with one log law have replacement means 1/4, 1/2, and 0, and the coarse identified interval [0, 1/2] strictly contains {1/4}.
- **Injectivity needs two loss values (T1-6) and prefix-dependent feasible sets (T1-15)** (supplementary check; injectivity lemma archived in `supplement/appendix-E.md`). With one loss value, summaries with different continuing mass give one identified set. With prefix-dependent feasible sets, a constant log keeps (C, u) = (0, 1) constant while the saturated mean sets are [0, 1], [1/2, 3/2], and [1, 2]; the reduced signature separates the fibre.
- **Announced gate (T1-11).** The agent proposes a benign or a risky call with probability 1/2 each, an executed risky call causes harm 1, and the replacement aborts flagged calls with valuation delta_0. Replay predicts harm 0; announcing the gate in the prompt lets the agent rewrite risky calls so the monitor misses them, and the deployed harm is 1/2. This violates (A1) with the prompt outside the declared input, or (A2) once the announcement enters it.

### Records That Leave a Gate Change Open (`verify_diagnostic.py`)

- **Recovery.** Independent Bernoulli variables S, B, V, H with parameters q, r, g, h stand for stale state, a proposal, a gate block, and recovery, with damage D = S B (1 - V)(1 - H), goal failure U = 1 - (1 - S) B (1 - V), and cost 1 + 2B + 3 S B (1 - V) H. For q = 0.2, r = 0.8, g = 0.5, raising h from 0.25 to 0.75 lowers damage probability from 0.06 to 0.02 and raises P(cost > 3) from 0.02 to 0.06, while goal failure stays 0.68.
- **Looser gate.** With r = 1, g = 1, h = 0 and a record of (B, D, cost), q = 0.1 and q = 0.9 give the same record (1, 0, 3) with probability one, yet replacing the gate by g = 0 gives damage 0.1 and 0.9. The paper keeps this instance in two sentences.
- **Stricter gate.** The omitted-harm-timing instance of Appendix A.3 (`app:diagnostic`): every p in {0, 1/4, 1/2, 1} gives one coarse record law, the replayed harm and an independent forward run both equal p, and the fibre condition fails.

### Supported Continuation and Model Updates (`verify_supported.py`)

- **Hidden inputs.** `check_hidden_baseline_input`: (G2) fails, and two mechanisms with equal record laws of (A, Y) give 1/2 against 3/4. `check_hidden_replacement_input`: (G4) fails, giving 3/8 against 5/8. `check_loss_value_not_enough`: recording only the loss value instead of its inputs gives 0 against 1/2.
- **Likelihood-weighting identity and overlap.** `check_general_formula`, `check_propensity_conditioning`, and `check_support_without_overlap` check the likelihood-weighting identity, the need to condition the propensity on later unaffected coordinates, and a case where (G1) holds and overlap fails (supplementary checks not used in the paper).
- **Declared inputs decide zero-agreement identification.** In `check_zero_agreement_identified`, declaring the outcome kernel on (U, A) instead of A makes the reached inputs null, and the replacement risk fills [0, 1].
- **Interface condition.** `check_interface_includes_state`: comparing only the action gives agreement mass 1 with unequal restricted measures, while comparing (action, memory) gives mass 1/2 and equal measures.
- **Contribution without a recorded loss.** `check_contribution_needs_recorded_loss`: equal record laws of (U, A) and agreement mass 1/2, but P(L = 1, agreement) is 1/8 against 3/8.

### Unsupported Inputs (`verify_unsupported.py`)

- **Non-convex image.** Two unknown kernels read only the retry, with X = N1 + 2 N2; every image law satisfies P(0)P(3) = P(1)P(2), so the midpoint of delta_0 and delta_3 is not in the image (supplementary check; the example is given here).
- **Shared null inputs.** T1-14 in the coordinate model: both types reach one null block, and the image is the single law Bern(1/2).
- **Saturated extreme.** `check_saturated_extreme`, `check_part_f`, and `check_pivot_without_onto` check the pivot conditions (P1) to (P3) and the equality of the image with the outer set of Proposition E.1.1 (`prop:replay-cont`).
- **Block and retry with mixed support.** The gate blocks high-score calls and reports the block through the tool-error message. The identified harm is [43/192, 91/192], inside the outer bound [9/64, 41/64]; treating the supported input (a, err) as null gives the larger outer set [1/8, 43/64].

### Component Evidence and Composition (`verify_coupling.py`, `verify_eval_awareness.py`, `verify_composition_replacement.py`)

- **How (CI) fails.** Pairwise without mutual independence: with S constant, L1 and L2 independent fair bits, and L3 = L1 xor L2, every pair is independent, yet P(L1 = L2 = L3 = 1) = 0 against the product 1/8. Direct handoff: component 2 copies component 1's fair bit, so both fail with probability 1/2 against 1/4. Common effect: with S = L1 + L2, both fail with probability 0 given S = 1 against 1/4.
- **Shared outage.** Two booking paths share one provider; the logged flag S has P_S(0) = 3/4 and P_S(1) = 1/4, an unlogged outage fails both paths with probability 1/2 when S = 1, and private faults have probability 1/10 and 1/5. Both paths fail with probability 39/400 under the product rule, 11/80 under the shared outage, and anywhere in [1/20, 9/40] without a dependence restriction; linked records separate the two mechanisms.
- **The event interval does not determine linear queries.** For component costs uniform on {0, 1, 2} and one state, two couplings both attain the upper bound 2/3 for P(L1 >= 1, L2 >= 1), yet P(L1 + L2 >= 3) is 1/3 under one and 2/3 under the other.
- **Oversight cues (Remark G.4.3 (`rem:p3-eval`)).** If unseen cues have deployment probability 1/2 and the seen half splits 1/4 and 1/4 between two cues with test harm rates 1/10 and 1/5, the interval is [3/40, 23/40]. With an unrecorded cue and test cue law (1/2, 1/2), testing gives only the aggregate rate 3/20; with deployment cue law (3/4, 1/4) and an unchanged kernel, the deployment rate lies in [3/40, 9/40].
- **Budget, stale cache, and outage as replacements.** The budget replacement gives the identified failure interval [1/20, 11/20]; the replay agreement set contributes 1/20 and the continuing mass is 1/2. The unlogged stale cache gives 1/10 against 11/20. Routing path 2 through path 1's status gives 39/400; also sharing the outage gives 11/80.
